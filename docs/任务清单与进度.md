## 二、本轮新增（v0.3）

### 1. 隐私占用指示（F-12）✅

**功能**：麦克风或摄像头被打开时，胶囊立刻提示是谁在用，可一键跳到隐私设置。

**数据来源**：`HKCU\...\CapabilityAccessManager\ConsentStore\{microphone,webcam}`
—— Windows 自己记录每次隐私设备访问，`LastUsedTimeStop == 0` 表示正在使用。
这是系统级事实，任何应用（含 UWP）调用都会被记录，不需要 hook。

**关键取舍**：
- 只在「正在使用」时上岛，用完即撤 → 符合 PRD 时效性闸门
- 硬抢占（`HardPreempt`），优先级 75 → 隐私不该被音乐盖住
- 3 秒轮询一次 → 这类状态变化本身不快，没必要更勤

**本机验证**：
```
正在使用的条目数 = 0   → 岛上无隐私提示（正确，本机确实没人在用）
```

⚠️ **诚实说明**：我**没有**完成「真实占用 → 检测到 → 释放 → 撤下」的完整闭环验证。
试过三种方式都失败：UWP 录音机在沙箱里起不来、`waveIn` 直接占用不写该注册表、
跨进程工具被作业对象回收。检测逻辑本身经过了数据结构级验证（能正确解析 15 条历史记录、
正确区分 0 与非 0），但触发路径未经端到端确认。

### 2. 性能实测（补充 PRD 缺失的量化数据）

之前 PRD 里的性能指标是我拍的，这次全部实测：

| 指标 | PRD 要求 | 实测 | 判定 |
|---|---|---|---|
| **空闲 CPU** | ≤ 0.3% | **0.026%** | ✅ 超出要求 11 倍 |
| 活跃刷新 CPU（4 次/秒） | — | 0.166% | ✅ 可忽略 |
| 10 秒句柄增长 | 无泄漏 | +5 | ✅ |
| 空闲内存 | ≤ 60 MB | **84 MB** | ⚠️ 见下 |

**内存构成**（逐层装载测得）：

| 层 | 占用 | 可回收 |
|---|---|---|
| 纯 .NET 运行时 | 24.5 MB | ❌ |
| WPF 窗口构造 | +16.0 MB | ❌ |
| WPF 首次渲染管线 | +20.8 MB | ❌ GC 管不到 |
| 首次渲染内容 | +3.9 MB | 部分 |
| 5 个数据源 | **+0.4 MB** | ✅ 可忽略 |
| 托盘 NotifyIcon | +7.0 MB | ❌ |

**结论**：数据源不是瓶颈，84 MB 是 WPF 桌面应用的框架底线。
对比本机其它常驻程序：Edge 单个渲染进程 1164 MB、资源管理器 294 MB。

**为什么不用 `EmptyWorkingSet` 强压**：
实测能把工作集从 84 MB 压到 4 MB，但**私有内存仍是 71.6 MB**——只是换到页面文件。
代价是胶囊重绘要 page fault 换回来，对音乐进度条、倒计时这类持续刷新的场景反而更耗电。

**采用的策略**（保守）：只在连续 3 分钟无上岛活动、槽位为空、卡片未展开时才整理。
实测确认：有内容时保持 84 MB 不动，行为正确。

**指标校准建议**：把 PRD 的「≤ 60 MB」改为「≤ 90 MB」，并把「空闲 CPU ≤ 0.3%」提到首位——
CPU 才影响发热和续航，84 MB 在页缓存充足的机器上不构成压力。

## 六、如何构建与分发

```powershell
# 1. 构建
powershell -NoProfile -ExecutionPolicy Bypass -File .\islet\build.ps1

# 2. 跑单测（33 项）
powershell -NoProfile -ExecutionPolicy Bypass -File .\islet\build.ps1 -Test

# 3. 生成安装包
powershell -NoProfile -ExecutionPolicy Bypass -File .\islet\package.ps1

# 产物：build\dist\IsletSetup.exe
```

**分发**：把 `IsletSetup.exe` 发给用户，双击即可。无需管理员权限，安装到用户目录。
